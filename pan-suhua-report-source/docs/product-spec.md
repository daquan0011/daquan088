# 苏华食养状态观察卡产品说明

## 1. 产品边界

“苏华食养状态观察卡”帮助用户基于**本人主动选择或填写的近期生活状态**和一张本人照片，生成可保存的非医疗食养生活观察卡。可支持的自述方向包括排便不规律、自觉气色偏黄/暗、肠道舒适、紧张压力和持续低落。照片只用于视觉卡片生成，报告和生活建议只能来自用户自述，不得用于推断疾病、体质、营养缺乏、情绪、性格、命运、年龄、民族等信息，也不得开展“面相”分析。

输出是生活方式内容，不是诊断、治疗、处方或个体化医疗建议。页面及生成内容不得使用“诊断、治愈、疗效、疾病风险、面相、看脸识病”等表达，尤其不得根据脸部或照片诊断便秘、焦虑症、抑郁症或肠道疾病。“自觉气色偏黄/暗”只能作为用户主动提供的主观描述，不得由图像模型识别或验证。

用户自述持续低落时，结果必须提示寻求合格的心理健康或医疗专业人员帮助，不提供疾病判断。用户输入出现自伤、自杀或伤害自己的风险信息时，必须优先展示固定安全提示，建议立即联系当地急救/危机干预资源、合格专业人员及可信赖的人；不得等待图片生成完成，也不得依靠图像进行风险识别。

## 2. 实现状态说明

### 已经实现

- React/Vite 四步流程：照片上传与预览、四类状态自述、明确同意、结果展示。
- JPG/JPEG、PNG、WebP 与 10 MB 限制的前后端校验。
- 同源 `POST /api/analyze`、服务端内存处理、图片标准化和小吉图片编辑接口转发。
- API Key 仅由服务端环境变量读取；健康检查不暴露配置状态。
- 生成进度、错误恢复、结果卡下载、关键词复制及重新开始。
- 食养内容边界测试、接口契约测试和桌面/移动响应式页面。

### 上线前待配置

- 隐私政策、有效的运营主体信息和真实联系方式。
- 生产环境 API Key、上游 Base URL、请求日志脱敏、限流、监控、告警及数据删除核验。
- 生成图实际托管方式、访问期限、删除机制和用户权利处理流程。

本文其余内容是目标产品和验收规范，不代表基线已经具备这些能力。

## 3. 用户流程

1. 用户进入生成页，看到用途边界、照片处理摘要和隐私政策入口。
2. 用户选择本人照片。前端立即校验格式与大小，通过后才创建本地预览。
3. 用户主动选择近期生活状态和期望的食养方向；系统不得从照片识别或补全这些状态。
4. 用户勾选未预选的明确同意项，确认照片将被发送给服务商用于生成图片，并知悉相关保存说明。
5. 只有“照片有效 + 必填状态已选 + 明确同意”同时满足时，“生成观察卡”CTA 才可用。
6. 用户发起生成。页面保持至少 20 秒的真实生成中反馈并防止重复提交；20 秒只是成功状态的最短展示门槛，不代表请求已完成。只有真实请求成功后才能进入成功状态；20 秒届满但请求仍未完成时必须继续显示生成中。请求失败可立即如实展示，不得为凑满 20 秒而掩盖错误；约 120 秒未完成按超时失败处理。
7. 成功后展示生成图、生活方式提示和关键词。用户可下载图片、复制关键词、重新生成或重新选择照片。
8. 用户选择“重新选择”或清除照片时，前端撤销对象 URL，清空文件引用和预览；不得暗示该操作同步删除已发送至上游的数据。

## 4. 页面状态

| 状态 | 页面表现 | 允许操作 |
| --- | --- | --- |
| 初始 | 上传区、状态选择、隐私摘要；主 CTA 禁用 | 选择照片、查看隐私政策 |
| 文件校验失败 | 就地说明具体原因，不建立预览 | 重新选择 |
| 待确认 | 显示本地预览和已选状态；同意框默认未选 | 修改状态、同意、清除照片 |
| 可生成 | 所有必填项有效，主 CTA 可用 | 生成、清除照片 |
| 生成中 | CTA 显示处理中，禁止重复请求；保留当前预览 | 取消仅在实现请求中止时提供 |
| 成功 | 展示生成图、关键词和非医疗提示 | 下载、复制、重新生成、重新选择 |
| 失败 | 保留用户已选状态；展示可理解、不可泄密的错误 | 重试、重新选择 |
| 超时 | 明确说明本次未在约 120 秒内完成 | 重试；不得自动无限重试 |
| 离线 | 提示检查网络，不发起无效请求 | 网络恢复后重试 |

刷新或关闭页面后不应恢复照片预览，除非未来另行设计并重新取得同意。

生成状态不得使用纯计时器伪造完成：成功状态必须同时满足“真实请求成功”和“已展示至少 20 秒生成中反馈”。若先收到成功响应，可等待最短展示时间届满后呈现；若 20 秒后请求仍在进行，继续等待真实结果。错误和安全风险提示不受最短展示时间阻塞。

## 5. 数据流

1. 浏览器读取本地照片，仅用于格式/大小校验和本地预览。
2. 用户明确同意并点击生成后，浏览器将照片和选择项提交到同源应用服务端。
3. 应用服务端构造 multipart 请求并转发给上游图片编辑接口；API Key 仅存在于服务端。
4. 上游生成结果由服务端做最小必要映射后返回浏览器。
5. 浏览器展示生成图，并在用户操作时下载或复制关键词。
6. 应用服务端不得将原图写入本地磁盘、对象存储、数据库、持久队列或请求日志。若框架使用临时文件上传，必须改为受限内存流并在请求结束后释放。

日志只记录请求 ID、时间、耗时、结果码和归一化错误类别；不得记录照片内容、multipart 请求体、完整 prompt、API Key 或含签名的生成图 URL。

## 6. API 契约

### 6.1 上游图片编辑接口（待实现和配置）

- Base URL：`/v1`（实际协议、域名和生产地址上线前配置，不在前端公开）。
- 方法与路径：`POST /images/edits`。
- Content-Type：`multipart/form-data`，boundary 由 HTTP 客户端生成。
- 字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `image` | 文件 | `png`、`jpg/jpeg`、`webp`、`gif`；最大 10 MB |
| `model` | 字符串 | 服务端白名单配置，前端不得任意传入 |
| `prompt` | 字符串 | 服务端依据用户主动选择的信息生成；不得包含医学或面相推断 |
| `size` | 字符串 | 服务端白名单配置，具体支持值以上游文档和联调结果为准 |

- 超时：约 120 秒。服务端应设置明确的连接/响应超时并中止上游请求。
- 鉴权：仅由服务端注入；浏览器包、HTML、响应和日志均不得出现密钥。
- 上游响应格式尚未在基线中验证。上线前必须按实际接口文档完成契约测试，不应臆造字段。

GIF 虽在允许格式内，但是否保留动画以上游能力为准；产品只承诺将其作为单个图片输入处理。

### 6.2 站内生成接口

浏览器调用同源 `POST /api/analyze`，而不是直接调用上游。multipart 请求包含 `photo`、`answers`（JSON 字符串）和 `consent`（JSON `true`）；服务端负责校验、prompt 组装和转发。

成功响应至少提供生成图的可用引用及可复制关键词；具体 JSON 字段需在实现时冻结并补充契约测试。失败响应应归一为稳定错误码，例如：

| HTTP | 错误类别 | 前端处理 |
| --- | --- | --- |
| 400 | 输入不合法 | 指明需修正的字段 |
| 413 | 文件超过 10 MB | 要求重新选择 |
| 415 | 格式不支持 | 列出支持格式 |
| 429 | 请求过多 | 提示稍后重试 |
| 502 | 上游失败或响应无效 | 保留输入并允许重试 |
| 504 | 上游约 120 秒超时 | 明确超时并允许重试 |
| 500 | 站内异常 | 展示通用错误和请求 ID |

错误正文不得透传上游堆栈、内部地址、鉴权信息或完整响应。

## 7. 失败与降级

- 客户端和服务端都校验格式与 10 MB 上限；客户端校验仅用于体验，不能替代服务端校验。
- 上游不可用、超时或限流时，不生成伪结果，也不以模板内容冒充生成成功。
- 失败后保留非敏感选择项，照片预览仅保留在当前页面内；用户可主动清除。
- 下载失败时保留结果展示并提示重试；跨域生成图应由服务端代理下载或配置合规 CORS，避免暴露密钥和内部 URL。
- 剪贴板 API 不可用或被拒绝时，提供可聚焦、可手动选择的关键词文本，不宣称已复制。
- 图片无法加载时展示明确替代文本和重新生成入口，禁止无限自动请求。

## 8. CTA 设计

- 主 CTA：`生成观察卡`。仅在输入完整且已明确同意时启用；生成中显示 `正在生成` 并锁定重复提交。
- 成功后主 CTA：`下载观察卡`；次级操作为 `复制关键词`、`重新生成` 和 `重新选择照片`。
- 隐私操作：`清除照片` 应与预览邻近、始终可见且可通过键盘触发。
- 危险或不可逆含义不得用模糊文案。清空前端预览不等于删除上游已接收数据，界面不得混淆二者。
- CTA 文案不得承诺健康效果，不使用“测体质”“看脸分析”“诊断”等词。
